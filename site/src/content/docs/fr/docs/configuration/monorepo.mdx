title: Monorepo

import { Tabs, TabItem, Aside } from '@astrojs/starlight/components';

FerrFlow considère un repository comme un monorepo lorsque la configuration définit plus d'un package. Chaque package est versionné indépendamment en fonction de son propre historique git.

## Isolation des packages

FerrFlow utilise les préfixes de chemin pour déterminer quels commits appartiennent à quel package. Seuls les commits qui touchent des fichiers sous `path` (ou `sharedPaths`) déclenchent une release pour ce package.

<Tabs syncKey="config-format">
  <TabItem label="JSON">
    ```json title="ferrflow.json"
    {
      "package": [
        {
          "name": "api",
          "path": "packages/api"
        },
        {
          "name": "site",
          "path": "packages/site"
        }
      ]
    }
    ```
  </TabItem>
  <TabItem label="TOML">
    ```toml title="ferrflow.toml"
    [[package]]
    name = "api"
    path = "packages/api"

    [[package]]
    name = "site"
    path = "packages/site"
    ```
  </TabItem>
  <TabItem label="JSON5">
    ```json5 title="ferrflow.json5"
    {
      package: [
        {
          name: "api",
          path: "packages/api",
        },
        {
          name: "site",
          path: "packages/site",
        },
      ],
    }
    ```
  </TabItem>
  <TabItem label="YAML">
    ```yaml title="ferrflow.yaml"
    package:
      - name: api
        path: packages/api
      - name: site
        path: packages/site
    ```
  </TabItem>
</Tabs>

## Dépendances partagées

Si vous avez du code partagé entre packages (ex. une bibliothèque `packages/shared/`), déclarez-le comme entrée `sharedPaths`. Un changement dans un chemin partagé déclenche une release pour chaque package qui le référence :

<Tabs syncKey="config-format">
  <TabItem label="JSON">
    ```json title="ferrflow.json"
    {
      "package": [
        {
          "name": "api",
          "path": "packages/api",
          "sharedPaths": ["packages/shared/"]
        },
        {
          "name": "site",
          "path": "packages/site",
          "sharedPaths": ["packages/shared/"]
        }
      ]
    }
    ```
  </TabItem>
  <TabItem label="TOML">
    ```toml title="ferrflow.toml"
    [[package]]
    name = "api"
    path = "packages/api"
    shared_paths = ["packages/shared/"]

    [[package]]
    name = "site"
    path = "packages/site"
    shared_paths = ["packages/shared/"]
    ```
  </TabItem>
  <TabItem label="JSON5">
    ```json5 title="ferrflow.json5"
    {
      package: [
        {
          name: "api",
          path: "packages/api",
          sharedPaths: ["packages/shared/"],
        },
        {
          name: "site",
          path: "packages/site",
          sharedPaths: ["packages/shared/"],
        },
      ],
    }
    ```
  </TabItem>
  <TabItem label="YAML">
    ```yaml title="ferrflow.yaml"
    package:
      - name: api
        path: packages/api
        sharedPaths:
          - packages/shared/
      - name: site
        path: packages/site
        sharedPaths:
          - packages/shared/
    ```
  </TabItem>
</Tabs>

## Dependances entre packages

Utilisez `dependsOn` pour declarer qu'un package depend d'un autre. Quand une dependance est publiee, le package dependant recoit automatiquement un bump patch — meme si aucun de ses propres fichiers n'a change. La cascade est transitive : si `app` depend de `cli` et `cli` depend de `core`, publier `core` bumpe aussi `cli` et `app`.

<Tabs syncKey="config-format">
  <TabItem label="JSON">
    ```json title="ferrflow.json"
    {
      "package": [
        {
          "name": "core",
          "path": "packages/core"
        },
        {
          "name": "cli",
          "path": "packages/cli",
          "dependsOn": ["core"]
        },
        {
          "name": "app",
          "path": "packages/app",
          "dependsOn": ["cli"]
        }
      ]
    }
    ```
  </TabItem>
  <TabItem label="TOML">
    ```toml title="ferrflow.toml"
    [[package]]
    name = "core"
    path = "packages/core"

    [[package]]
    name = "cli"
    path = "packages/cli"
    depends_on = ["core"]

    [[package]]
    name = "app"
    path = "packages/app"
    depends_on = ["cli"]
    ```
  </TabItem>
  <TabItem label="JSON5">
    ```json5 title="ferrflow.json5"
    {
      package: [
        {
          name: "core",
          path: "packages/core",
        },
        {
          name: "cli",
          path: "packages/cli",
          dependsOn: ["core"],
        },
        {
          name: "app",
          path: "packages/app",
          dependsOn: ["cli"],
        },
      ],
    }
    ```
  </TabItem>
  <TabItem label="YAML">
    ```yaml title="ferrflow.yaml"
    package:
      - name: core
        path: packages/core
      - name: cli
        path: packages/cli
        dependsOn:
          - core
      - name: app
        path: packages/app
        dependsOn:
          - cli
    ```
  </TabItem>
</Tabs>

<Aside type="note">
`dependsOn` est different de `sharedPaths`. Les chemins partages declenchent un bump quand des fichiers dans le repertoire partage changent. `dependsOn` declenche un bump quand un autre **package** est publie, independamment des fichiers modifies.
</Aside>

## Format des tags git

Par défaut, les tags en monorepo utilisent le format `{name}@v{version}` :

```
api@v1.2.0
site@v0.4.1
```

Configurez cela avec le champ `tagTemplate` :

<Tabs syncKey="config-format">
  <TabItem label="JSON">
    ```json title="ferrflow.json"
    {
      "workspace": {
        "tagTemplate": "{name}@v{version}"
      }
    }
    ```
  </TabItem>
  <TabItem label="TOML">
    ```toml title="ferrflow.toml"
    [workspace]
    tag_template = "{name}@v{version}"
    ```
  </TabItem>
  <TabItem label="JSON5">
    ```json5 title="ferrflow.json5"
    {
      workspace: {
        tagTemplate: "{name}@v{version}",
      },
    }
    ```
  </TabItem>
  <TabItem label="YAML">
    ```yaml title="ferrflow.yaml"
    workspace:
      tagTemplate: "{name}@v{version}"
    ```
  </TabItem>
</Tabs>

Pour un repo mono-package, le défaut est `v{version}` (sans préfixe de nom).

FerrFlow recherche le tag le plus récent correspondant au modèle pour déterminer quels commits sont nouveaux.

## Cadences indépendantes

Les packages sont publiés indépendamment. Dans une seule exécution de `ferrflow release` :

- `api` peut passer de `1.2.0` → `1.3.0` (nouveau commit `feat:`)
- `site` peut passer de `0.4.0` → `0.4.1` (uniquement des commits `fix:`)
- `shared` peut ne pas être publié (uniquement des commits `chore:`)

## Surcharges par package

Chaque package peut surcharger la stratégie de `versioning` et le `tagTemplate` du workspace :

<Tabs syncKey="config-format">
  <TabItem label="JSON">
    ```json title="ferrflow.json"
    {
      "workspace": {
        "versioning": "semver",
        "tagTemplate": "{name}@v{version}"
      },
      "package": [
        {
          "name": "api",
          "path": "packages/api",
          "versioning": "calver"
        },
        {
          "name": "site",
          "path": "packages/site",
          "tagTemplate": "site-v{version}"
        }
      ]
    }
    ```
  </TabItem>
  <TabItem label="TOML">
    ```toml title="ferrflow.toml"
    [workspace]
    versioning = "semver"
    tag_template = "{name}@v{version}"

    [[package]]
    name = "api"
    path = "packages/api"
    versioning = "calver"

    [[package]]
    name = "site"
    path = "packages/site"
    tag_template = "site-v{version}"
    ```
  </TabItem>
  <TabItem label="JSON5">
    ```json5 title="ferrflow.json5"
    {
      workspace: {
        versioning: "semver",
        tagTemplate: "{name}@v{version}",
      },
      package: [
        {
          name: "api",
          path: "packages/api",
          versioning: "calver",
        },
        {
          name: "site",
          path: "packages/site",
          tagTemplate: "site-v{version}",
        },
      ],
    }
    ```
  </TabItem>
  <TabItem label="YAML">
    ```yaml title="ferrflow.yaml"
    workspace:
      versioning: semver
      tagTemplate: "{name}@v{version}"

    package:
      - name: api
        path: packages/api
        versioning: calver
      - name: site
        path: packages/site
        tagTemplate: "site-v{version}"
    ```
  </TabItem>
</Tabs>

<Aside type="tip">
Utilisez `ferrflow check` pour prévisualiser exactement quels packages seraient publiés et à quelle version avant de lancer une release.
</Aside>
